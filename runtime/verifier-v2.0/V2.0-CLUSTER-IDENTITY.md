- Chain: 962421430
- Block: 0
- Source: Genesis block-zero hash, recorded / collected via
  `eth_getBlockByNumber ["0x0", false]` (hash field), as in prior records.
- **What it is:** an identifier / root label for the V2.0 cluster.
- **What it is not:**
  - Not derived from the pair. The pair diagnostic
    `SHA256(Source1‖Source2)` is a different value, and pair commitments are
    downstream of genesis input, not a derivation of genesis.
  - Not a signature, not a verification proof, not a settlement proof.
  - Not activation of any financial operation.
  - Not a lift of the quarantine on the former cluster root.

## Former cluster root — quarantine route preserved

The former cluster root is preserved **only** in `evidence/quarantine/`,
labeled DO-NOT-USE, with its quarantine note and verification package.
It is not deleted, not hidden, and not used as a live root. Preserving it
as evidence does not make it current, and replacing it as the live root
does not lift its quarantine.

## Break / complete analysis (summary; full analysis in MERGE-REPORT)

Replacing the live cluster root with the Genesis hash:

- **Does it break live code?** No functional break was found in the merged
  code, because the root is used as an identifier / attestation label, not
  as a cryptographic key or an external settlement reference. The files
  that had to change were exactly the 9 financial demo / engine files that
  hard-coded the old root, plus their mock-secret derivatives (see
  AUDIT-LOG). Those files were updated, and the unified tests pass.
- **What would have failed until updated?** Any test or demo asserting the
  old root value — principally the RWA tokenization test, which asserts
  `solvency.clusterStateRoot` equals the canonical cluster root. That test
  now asserts the Genesis value (via the kept constant name, documented
  in the code). Other financial tests compute their cluster root from
  their own payload, so they were not root-sensitive.
- **Does replacement complete V2.0?** No. Replacement alone completes
  nothing except the identifier change. Signing, binding, verification,
  activation, and freeze sign-off are all still outstanding (see
  MERGE-REPORT § "What is NOT completed").
