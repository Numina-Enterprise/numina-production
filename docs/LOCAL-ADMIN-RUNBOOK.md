# Local admin console and release keys: operations runbook

Status: working runbook, Nov 9 2026. Scope: the local-only console in `src/local/` and the
release signing keys (SKOTT34-*). Nothing in this runbook touches the public site, Cloudflare,
GitHub settings, treasury systems or any provider account.

## 1. Setup
1. Install Node 26.13.0 (the repo's `engines` pin) and run `npm ci` in the repository.
2. Run `npm run build`. Unpublished files land in `dist/private-downloads/`.
3. Choose an admin token: at least 16 random characters, for example
   `node -e "console.log(require('crypto').randomBytes(24).toString('base64url'))"`.
   Keep it in your password manager. Set it only in the shell that runs the console:
   `export NUMINA_LOCAL_ADMIN_TOKEN=...` (PowerShell: `$env:NUMINA_LOCAL_ADMIN_TOKEN='...'`).
   Never commit it, never put it in `.env` files that are synced, never paste it into chat.
4. Start: `npm run local-admin`. Open `http://127.0.0.1:8790/admin`.

## 2. Binding
- Default: `127.0.0.1:8790` (loopback only). Change the port with `--port` or `NUMINA_LOCAL_ADMIN_PORT`.
- LAN: `--host <one specific LAN IP> --allow-lan` (or `NUMINA_LOCAL_ADMIN_HOST` +
  `NUMINA_LOCAL_ADMIN_ALLOW_LAN=1`). `0.0.0.0`/`::` are refused. The console has no TLS: use LAN
  binding only on a trusted network segment, and stop the process when finished.
- Never expose the port through a router, tunnel or reverse proxy.

## 3. Admin token
- Read actions (status, MCP config, route config, file list) need no token; write actions
  (save route config, add or remove downloads) need `Authorization: Bearer <token>`.
- Rotate: stop the console, set a new value, restart. There is no stored copy to revoke.
- If the token may have leaked: rotate it, then review `local-data/` for unexpected changes
  (`git status` does not track it; compare against your backup).

## 4. Release signing keys (generated on Vengeance)
Keys: SKOTT34-Ed25519 (required), ML-DSA, SLH-DSA (FIPS 204/205) and pre-standard FN-DSA.
- **Generation**: on Vengeance only, with the signing kit
  (`vengeance-signing-kit\README.md`): `node scripts\release-pq-keygen.mjs --out
  $env:USERPROFILE\.numina-release-keys --pub-out pubkeys`. The script refuses to overwrite,
  writes private keys only to that folder and prints only public keys.
- **Storage**: `C:\Users\sam\.numina-release-keys`, ACL restricted to Sam's account (`icacls`
  command in the kit README). Prefer a BitLocker-encrypted volume. Never copy private keys to the
  box, the repo, cloud drives, chat or email.
- **Backups**: one offline encrypted backup (for example an encrypted USB drive stored
  separately). Record the public key fingerprints
  (`Get-FileHash pubkeys\* -Algorithm SHA256`) in the backup log.
- **Rotation**: generate new keys with a new folder, commit the new public keys in
  `release-evidence/pubkeys/` in a reviewed commit, sign the next release with the new keys,
  then retire the old private keys (secure delete) after the release verifies in CI.
- **Revocation**: remove the public key file from `release-evidence/pubkeys/` in a reviewed
  commit; CI then rejects envelopes that rely on it. Record the reason and date in the release
  notes. Removing SKOTT34-Ed25519 blocks every deploy until a replacement is committed.
- **Compromise response**: (1) stop: do not merge or deploy; (2) revoke the public key as above
  and commit the replacement; (3) re-sign the current release with the new key; (4) review
  recent deploys against their signed statements (`node scripts/release-verify.mjs` on the
  matching commit); (5) rotate the admin token and any credentials stored on the same machine.

## 5. Recovery
- Console data lives in `local-data/` (route config and uploaded private downloads). Back it up
  with your normal encrypted backup; restore by copying the folder back.
- Build files in `dist/private-downloads/` are regenerated by `npm run build`.
- Lost signing key: treat as revocation (section 4) and generate a new key.

## 6. Logs
- The console logs one line per request to stdout: ISO time, method, path (no query string),
  status. Request bodies, headers and tokens are never logged.
- Capture logs if needed with `npm run local-admin 2>&1 | Tee-Object -FilePath local-admin.log`
  (PowerShell) or `| tee local-admin.log` and keep them out of the repository.
