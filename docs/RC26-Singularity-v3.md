# Numina rc26 singularity alignment

The rc26 runtime binds the preserved v1.8.0 core to the single canonical Numina root across L1–L5. The new signed binding is at /v1/release/core-binding. Its source and build hashes are also covered by the signed runtime declaration.

POST /v1/evidence/revoke is restored on the production runtime and canonical website, protected by the existing owner bearer identity. A revocation retains the original artifact and returns the first stored signed revocation on retries. Publishing this route does not revoke any existing record.

The authenticated treasury account view groups duplicate exact provider references while preserving all original account IDs and conflicting labels. There is one 500T NUSD native projection. Original plan and subsequent owner FUNDED_PLAN declaration remain separate signed history; no older snapshot replaces the current journal. Account views do not allocate or add balances.

The OS public shell and current plugin/integration documentation are aligned to rc26. Existing mobile binaries and their signing/store statuses are preserved. Native hosts load the canonical /app workspace. PWA update checks revalidate public shell content; no private API records are cached.

SLSA v1.2 Build L3 is the highest Build level. The retained historical L3 producer assessment applies only to the two artifacts from Numina 2.0.0 run 34717406980. This current source assembly does not claim L3.

The revocation adapter requires a specific existing 64-character lowercase hexadecimal record_id and a nonempty reason of at most 1,000 characters. Optional evidence must be an object. Missing fields, wildcards, bulk requests and extra command fields are rejected before forwarding. The runtime separately verifies owner authority and record existence.
